# 0032 — Epic 1.3 provider dependencies (Vercel AI SDK + provider packages)

**Status:** accepted
**Date:** 2026-06-14
**Implements:** ADR-0002 (provider abstraction = Vercel AI SDK behind `ModelPort`)

## Context

Epic 1.3 implements `ModelPort` with the Vercel AI SDK (ADR-0002) for Anthropic, OpenAI, Google,
and a local/OpenAI-compatible path. That requires adding the SDK core + provider packages as
runtime dependencies of `@keel/kernel`. Supply-chain rules apply from commit one (CONTRIBUTING
ground rule 9, `MASTER_SPEC.md` §5.3): exact pins, `ignore-scripts`, committed lockfile,
permissive-license-only, and the 7-day minimum-release-age policy (review-enforced under pnpm
9.9). This ADR records the exact set + the choices, mirroring ADR-0023 (Epic 1.2 tool deps).

## Decision

**Pinned set (all Apache-2.0; license gate passes):**

| Package | Pin | Role |
|---|---|---|
| `ai` | 6.0.197 | SDK core (`streamText`, `tool`, `jsonSchema`) |
| `@ai-sdk/anthropic` | 3.0.81 | Anthropic provider |
| `@ai-sdk/openai` | 3.0.68 | OpenAI provider |
| `@ai-sdk/google` | 3.0.80 | Google Gemini provider |
| `@ai-sdk/openai-compatible` | 2.0.48 | local / Ollama path (Ollama's OpenAI-compatible endpoint) |

- **Min-release-age (7 days) drove the pins, not "latest".** At install (2026-06-14) the latest
  releases of every package were published 2026-06-11/12 — **<7 days old**, which the policy
  forbids. The pins are the newest **≥7-day-old** versions of the **`ai@6` generation** (cutoff
  2026-06-07): `ai` 6.0.197 (2026-06-04), anthropic 3.0.81 (2026-05-28), openai 3.0.68
  (2026-06-04), google 3.0.80 (2026-05-27), openai-compatible 2.0.48 (2026-05-22). (Note:
  anthropic maintains a parallel 2.x line for `ai@5`; we pin the 3.x line to match `ai@6`.)
- **Exact-pinned, `ignore-scripts`, committed lockfile** (`.npmrc` enforces save-exact +
  ignore-scripts). Added in two isolated commits (anthropic+core for the walking skeleton;
  openai/google/openai-compatible for slice 8) so each dep addition is reviewable.
- **Peer compatibility:** the provider packages peer `zod ^3.25.76 || ^4.1.8`, satisfied by the
  repo's pinned `zod@3.25.76`. No peer on `ai` itself (alignment is via `@ai-sdk/provider*`).
- **Local/Ollama path uses `@ai-sdk/openai-compatible`** (point at `http://localhost:11434/v1`),
  matching the `"openai-compatible"` capability row. The community `ollama-ai-provider-v2` (also
  Apache-2.0) was evaluated and offers richer Ollama-native features (streaming tool calls,
  embeddings), but is **not needed** for the 4-provider scope — the OpenAI-compatible shim covers
  the "local first-class but feature-degraded" v1 goal (no caching, best-effort reasoning). It is
  a clean future addition (a 5th capability row + factory) if Ollama-native features are wanted.

## Consequences

- `@keel/kernel` gains five runtime dependencies; the SDK's streaming/tool-call churn is absorbed
  entirely behind `ModelPort` (ADR-0002), so a future SDK major bump touches only the adapter +
  its contract tests, never the kernel loop. The chunk-mapping verification against the installed
  types (slices 1–7) is the drift tripwire.
- Version bumps follow §5.3 + the manual min-release-age review until pnpm honors
  `minimum-release-age` natively (ADR-0018 / CONTRIBUTING note); Dependabot proposes, review pins.
- No native build step (`ignore-scripts`); SBOM + signed releases at release time (§5.3).
