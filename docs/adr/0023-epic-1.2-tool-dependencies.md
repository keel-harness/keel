# ADR-0023 — Epic 1.2 tool dependencies and the bash process model

- **Status:** Accepted
- **Date:** 2026-06-13
- **Deciders:** keel maintainers
- **Governs:** MASTER_SPEC §7 Epic 1.2, §5 (dependencies/supply chain); ADR-0021 (`ExecutorPort`); and the public tool/process tests.

## Context

Epic 1.2 implements the five core tools. Two need capability beyond the standard library: `bash` (run shell commands with a timeout, completion detection, and a no-orphan kill) and `search` (fast content/filename search). The charter mandates: permissive licenses only (Apache-2.0/MIT/BSD/ISC); `ignore-scripts=true` supply-chain hygiene; exact version pins; a 7-day minimum-release-age (review-enforced under pnpm 9.9 per `.npmrc`); determinism and hermetic CI; and "no convenience dependencies." Phase 1 is honest-no-enforcement — the warden (Phase 2) owns OS-level sandboxing.

## Decision

1. **Search → adopt `@vscode/ripgrep@1.18.0` (MIT), exact-pinned.** Prebuilt `rg` ships per platform in os/cpu-gated optional sub-packages (`@vscode/ripgrep-<os>-<arch>`); the umbrella package is a tiny script-free runtime resolver exporting `rgPath`. No postinstall, **no runtime network**, ignore-scripts-clean (the prebuild is a plain file loaded at runtime, not a build step); battle-tested by VS Code. Consumed via `rgPath` + `child_process.spawn`, with `RIPGREP_CONFIG_PATH` cleared from the child env and `--` before every user-controlled argument. Min-release-age (review-enforced) verified on the umbrella **and all twelve `@vscode/ripgrep-*` sub-packages** (published 2026-05-07, clearing the 7-day floor at adoption). The dependency is added to `@keel/kernel` in slice 1.2f.

2. **Bash → NO native dependency.** Use a stdlib persistent pipe-backed shell (`PipeShellSession`) behind a `ShellSession` interface. **Defer a true PTY:** `@lydell/node-pty` (MIT, prebuilt, no-script) is the only ignore-scripts-clean option but its `latest` is `1.2.0-beta.*` — below the production/exact-pin bar — and Microsoft's `node-pty` needs node-gyp at install (breaks `ignore-scripts`). A `PtyShellSession` is a future drop-in behind the same interface, needing no tool-contract or loop change. No native dependency enters keel in Phase 1.

3. **Bash process model (OS-privilege assumption).** The shell is spawned detached (a process-group leader); timeout/abort/`dispose` `SIGKILL` the group via `process.kill(-pgid)`. This rests on an OS-privilege assumption — successful group leadership on macOS and Linux — recorded here per the charter's "stop and ask" rule. **Honest scope (ground rule 4):** the group `SIGKILL` is *best-effort*. keel does not assert at spawn that group leadership took (Node exposes no clean `getpgid`, and `process.kill(-pid,0)` only proves the group exists, not that the shell leads it), so a failed-leadership case degrades to an *orphaned-child risk* — observable as `ESRCH` — rather than failing closed. The no-orphan `ESRCH` integration test is the empirical backstop; a spawn-time leadership assertion is a hardening follow-up. Completion uses a CSPRNG-nonce marker; the command's stdin is `</dev/null`; stderr is merged into stdout. The no-leak guarantee covers runaway/timeout/abort, **not** intentionally-backgrounded jobs (the model's choice).

## Consequences

- **Positive:** zero native dependencies in Phase 1; deterministic, hermetic tests; clean supply chain; the `ShellSession` and `ContainedPath` seams keep the design forkable and Phase-2-ready.
- **Negative:** `bash` has no TTY semantics (no `isatty`/color/interactive REPLs; interactive stdin unsupported) until a `PtyShellSession` lands. The loop's global `infraTimeout` interacts with `bash`'s own timeout — contract: `bash`'s `MAX_TIMEOUT_MS` ceiling must be strictly less than any `infraTimeout.toolMs` the kernel configures (design spec §7).
- **Surface for Phase 2:** `search` spawning `rg` directly is a second uncontained process surface the Phase-2 `WardenExecutor` must also bring under sandbox/policy.

## Alternatives considered

- System `rg` + `keel doctor` check — rejected: first-run friction, cross-machine version skew, and non-determinism.
- Pure-JS search — rejected: reinvents a mature, fast tool (against the reuse thesis).
- One-shot `spawn` per `bash` call — rejected: drops borrowed technique 4 (marker completion) and cross-call cwd/env persistence.
- True PTY now — rejected: the only ignore-scripts-clean distribution is beta-only, against the exact-pin/production bar.
