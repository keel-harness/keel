# 0042 — Switch the Terminal-Bench pin from 2.0 to 2.1 (the verified dataset)

**Status:** accepted
**Date:** 2026-06-16
**Relates to / amends:** ADR-0022 (OQ-3/OQ-4 — this changes the OQ-4 *dataset* pin from `terminal-bench@2.0`
to `terminal-bench/terminal-bench-2-1`; the model + cost caps + reference harness Terminus-2 are
unchanged). ADR-0041 (Harbor license gate). Epic 1.11 plan slice 5 / QR-6 (which flagged TB-2.0 vs 2.1 as
the open question to resolve).

## Context

QR-6 required resolving TB-2.0 vs TB-2.1 before the parity gate. The facts (researched 2026-06-16 against
the harbor registry + both task repos):

- **TB-2.0** — `harbor-framework/terminal-bench-2`, 89 tasks, Apache-2.0; reachable via the registry
  shorthand `harbor run -d terminal-bench@2.0`.
- **TB-2.1** — `harbor-framework/terminal-bench-2-1`, Apache-2.0; the README calls it *"a more verified
  iteration of Terminal-Bench 2.0"*: **26 of the 89 tasks fixed IN PLACE** (bug fixes, timeout/resource
  adjustments, and hardening against reward-hacking — many sourced from Z.ai's TB-2.0-Verified updates).
  **Same 89 task ids; none added or removed.** Not reachable via the `@2.0`/`@2.1` registry shorthand —
  run with `harbor run --dataset terminal-bench/terminal-bench-2-1`.

For a **kill-criterion parity gate**, task correctness + reward-hacking resistance matter directly: a
buggy task or a reward-hackable verifier produces a misleading score on both keel and the reference. The
"more verified" set is the better gate anchor.

## Decision

**Pin the dataset to TB-2.1** (owner decision, 2026-06-16). Because the 89 task ids are identical between
2.0 and 2.1, **the owner-approved `keel-tb2-25` subset (and the `keel-tb2-5` smoke + the held-out 10) are
preserved unchanged** — every id is present in 2.1 (verified). Only the pin coordinates + the invocation
change:

- **Dataset / invocation:** `harbor run --dataset terminal-bench/terminal-bench-2-1` (replaces
  `-d terminal-bench@2.0`).
- **Pinned task repo:** `harbor-framework/terminal-bench-2-1` @ commit
  **`c5ee500c185224c97cd6caff7866a990a0057f41`** (byte-reproducibility).
- **Catalog snapshot:** `packages/eval/src/tb2/catalog.json` regenerated from the 2.1 `task.toml` files at
  that commit — `version: "2.1"`, the 2.1 pin, and the 89 tasks' 2.1 metadata. Difficulty/category
  distributions are unchanged from 2.0 (medium 55 / hard 30 / easy 4; the same 16 categories), so the
  stratification of `keel-tb2-25` (all 16 categories, medium 16 / hard 7 / easy 2) still holds.
- The keel suite label stays `terminal-bench-2` (the 2.x family); the `version` field carries `2.1`.
- The reference harness stays **Terminus-2 via Harbor** (ADR-0022); it now runs against the 2.1 dataset.
  The reference baseline must still be **measured by us** on identical infra + model + the 2.1 subset
  (never a leaderboard number) — Appendix F's "any dataset change invalidates prior comparisons + needs a
  fresh reference measurement" applies (there is no prior measurement yet, so nothing is invalidated).

## Consequences

- The Harbor adapter is invoked with `--dataset terminal-bench/terminal-bench-2-1` (CONTAINER.md +
  the adapter README updated). The adapter code is unchanged — it installs + runs keel per task regardless
  of which dataset Harbor selects.
- The integrity test pins the 2.1 commit + dataset id; regenerating the catalog (or a future 2.x bump) is
  ADR-gated.
- TB-2.1 is on Harbor Hub (`terminal-bench/terminal-bench-2-1/latest`); pin to the commit above for
  reproducibility rather than `latest`.
